# 노션 포트폴리오 축약 레이아웃 설계

## 목표

개인 포트폴리오의 6개 상세 페이지를 레퍼런스 포트폴리오처럼 시각 자료 중심으로 재구성한다. 처음 보는 채용 담당자가 영상과 이미지, 짧은 설명만 훑어도 프로젝트와 담당 작업을 파악할 수 있어야 하며, 코드는 필요한 경우에만 토글을 열어 확인하도록 한다.

## 공통 페이지 구조

1. 프로젝트명과 한 줄 소개
2. 플레이 영상 또는 대표 이미지
3. 개발 기간, 팀 구성, 담당 역할, 기술을 담은 짧은 개요
4. 내가 구현한 핵심 작업 3~5개
5. 대표 구현 2~3개
   - 결과를 보여주는 GIF 또는 스크린샷
   - 문제 한 문장
   - 구현 방법 2~3문장
   - 결과 한 문장
6. 필요할 때만 여는 `핵심 코드 보기` 또는 `상세 구현 및 검증` 토글
7. 수상, 전시, 배포 링크처럼 바로 보여야 하는 결과

본문에는 다른 팀원의 작업을 넣지 않는다. 같은 사실을 개요, 작업 내용, 상세 구현에서 반복하지 않는다. `문제`, `판단`, `해결`, `결과`를 매번 별도 제목으로 나누지 않고 한 섹션 안에서 자연스럽게 연결한다.

## 레이아웃 원칙

- 영상과 GIF는 해당 프로젝트에서 가장 먼저 확인할 수 있는 위치에 둔다.
- 대표 구현은 가능하면 이미지와 설명을 2열로 배치한다.
- 하나의 구현에는 대표 GIF 1개를 사용하고, 정지 이미지는 비교가 필요한 경우에만 2장까지 사용한다.
- 긴 표는 제거하고 기간·인원·역할·기술처럼 스캔 가치가 있는 정보만 짧은 표로 유지한다.
- Mermaid와 장식 목적의 다이어그램은 사용하지 않는다.
- 코드 블록은 본문에 직접 노출하지 않고 토글의 자식 블록으로 이동한다.
- 코드가 없는 페이지도 환경 구성, 검증 조건, 제한 사항처럼 긴 설명은 상세 토글로 분리한다.

## 프로젝트별 구성

### Alice in Boardland

- 상단: 플레이 영상, 한 줄 설명, 담당 작업 4줄
- 대표 구현:
  1. UIButton과 UISlider — 상태 전환 GIF와 슬라이더 GIF
  2. 타일 선택부터 유닛 생성·규칙 설정 — 흐름 GIF
  3. 스킬 대상 검사와 소모 처리 — 스킬 GIF
- 코드: 기존 4개 코드 블록을 구현별 `핵심 코드 보기` 토글로 이동
- 결과: 전임교수상과 BIC 전시는 사진과 한 문장으로 유지
- 본문 목표: 약 2,300자

### Prism of Gray Paradise

- 상단: 플레이 영상, 한 줄 설명, 담당 작업 4줄
- 대표 구현:
  1. 픽셀 디졸브와 재구성 — GIF 2개
  2. 이동·대시·방향 애니메이션 — 짧은 구현 요약
  3. Excel 기반 5개 언어 텍스트·폰트 교체 — 다국어 화면
- 코드: 알파값 기반 유효 픽셀 계산 코드를 `핵심 코드 보기` 토글로 이동
- 본문 목표: 약 1,800자

### Sinclair

- 상단: 플레이 영상, 장비와 세대 성장 중심의 한 줄 설명
- 대표 구현:
  1. 창 표시 우선순위와 입력 전달 — 창 중첩 스크린샷과 설계 기록
  2. 드래그 앤 드롭 예외 복구 — `sinclair_drag_drop_restore_14.6-16.4s.gif`
  3. 장착 장비 계승과 마지막 세대 엔딩 판정 — 계승 이미지와 엔딩 이미지
- 코드: 현재 코드 블록을 `핵심 코드 보기` 토글로 이동
- 기존 선택지·수치 나열 표는 핵심 규칙 3줄로 축약
- 본문 목표: 약 2,200자

### VeyTrace

- 상단: 플레이 영상을 크게 배치하고 개발 중인 협동 액션 프로젝트임을 표시
- 대표 구현:
  1. 절차적 맵 배치 데이터 저장과 재적용
  2. 일반 몬스터·중간보스 행동 설계
  3. 3단계 보스 패턴과 인터럽트
  4. NetworkSync 기반 맵 동기화 검증
- 이미지가 추가되기 전에는 임의 프레임을 추출하지 않고 영상과 간결한 설명을 사용한다.
- 보스 세부 패턴, 서버 권한, 2·3인 검증 환경은 `상세 구현 및 검증` 토글로 이동
- 본문 목표: 약 2,700자

### Custom Unity MCP Server

- 상단: 원본 대비 포크 개선 비교 이미지
- 대표 구현:
  1. 응답 크기 절감
  2. 무한 대기와 Domain Reload 대응
  3. Unity 프로젝트 해석 계층
- 실측 방법, 재시도 규칙, 세부 오류 분석은 `측정 및 검증 상세` 토글로 이동
- 현재 수치 비교 이미지는 유지하고 표의 중복 설명은 제거
- 본문 목표: 약 2,400자

### AI 기반 팀 지식·개발 운영 시스템

- 상단: 시스템 목적과 전체 정보 흐름을 4줄 이내로 설명
- 대표 구현:
  1. Tailscale·Syncthing 기반 공용 Vault
  2. 회의록·기획·아트·Git·Airtable 정보 통합
  3. 근거 기반 Daily Todo와 근거 부족 시 추측 방지
  4. 코드 이해도와 안개구역 점검
- 이미지 8장은 관련 설명 바로 옆에 배치하되 한 섹션에 2장을 넘기지 않는다.
- 배포 절차와 제한 사항은 `운영 구조 및 한계` 토글로 이동
- 본문 목표: 약 2,500자

## 검증 기준

- 6개 페이지에서 본문에 직접 노출된 코드 블록이 0개다.
- 코드가 있는 페이지에는 코드 토글이 존재하고 토글 내부에 기존 코드가 보존된다.
- 모든 기존 영상 링크가 유지된다.
- Alice, Prism, Sinclair의 확정 GIF와 이미지가 의도한 구현 섹션에 배치된다.
- 메인 프로필 사진과 기존 수상·전시·측정·운영 증거 이미지는 삭제하지 않는다.
- 페이지별 본문 길이가 목표치에서 15%를 넘지 않는다.
- 동일 사실을 반복하는 문단과 설명용 대형 표가 제거된다.
- 수정 후 API 재조회와 공개 화면 확인을 모두 수행한다.
