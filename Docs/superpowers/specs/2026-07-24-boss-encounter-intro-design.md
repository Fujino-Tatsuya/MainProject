# 보스룸 진입·등장 연출·전투 전환 설계

작성일: 2026-07-24
대상 브랜치: `feature/map-player-merge`
상태: 구현 전 승인 설계

## 1. 목표

`MapScene`의 보스룸 진입부터 No.23 전투 시작까지를 하나의 서버 권한 시퀀스로 만든다.

완료 상태는 다음과 같다.

1. 생존 플레이어 1~3명이 보스룸의 서로 다른 안전 지점으로 이동한다.
2. 전원이 이동을 적용한 뒤 입력, 진행 중 공격·스킬, 버프·디버프, 콤보를 초기화한다.
3. No.23이 전투 로직이 정지된 상태로 상공에 스폰되고 `JumpAttack` 계열 착지 애니메이션을 재생하며 내려온다.
4. 착지 순간 각 클라이언트 화면에 카메라 흔들림과 먼지·작은 돌 VFX가 재생된다.
5. 우측 중앙부터 하단 영역에 대사 UI를 표시한다. 첫 문구는 정확히 `보스 등장.`이다.
6. 연출 중 ESC 스킵 투표를 받고, 현재 유효 참가자 전원이 동의하면 즉시 안전한 전투 상태로 수렴한다.
7. 연출 종료 시 모든 생존 참가자의 입력과 No.23의 BT를 같은 서버 전환에서 활성화한다.
8. 보스룸 바닥, 투명 경계, NavMesh가 플레이어 추락과 보스 이동 불가를 막는다.
9. 충전 패턴 때 `Env_Mv_bosscharger_upper` 4개가 바닥에서 올라와 피격 가능해지고, 파괴 또는 패턴 종료 후 다시 내려가 다음 패턴에 재사용된다.

## 2. 범위와 비범위

### 포함

- 보스룸 텔레포트 완료 확인과 겹침 방지
- 서버 권한 보스 등장 시퀀스
- 참가자 입력 잠금, 전투 상태 초기화, 연출 중 피해·상태이상 차단
- No.23 스폰, 낙하, 착지 애니메이션, 카메라 흔들림, 착지 VFX
- 페이지형 보스 대사 UI
- 인원수 기반 만장일치 ESC 스킵
- 사망·연결 해제 참가자의 즉시 정족수 제외
- No.23 BT 지연 시작
- 충전기 4개의 상승·피격·하강·재사용
- 보스룸 바닥/투명벽 충돌체와 NavMesh 포함·제외 규칙
- MPPM 1·2·3인 검증

### 제외

- Wells의 별도 등장 연출
- 보스 대사의 최종 문구·음성·로컬라이제이션 체계
- 새 Asset Store 패키지 도입
- 맵 생성 알고리즘 재작성
- 보스 전투 패턴 자체의 밸런스 변경
- SVN 소유 FBX, 텍스처, 오디오와 그 `.meta` 수정

## 3. 선택한 구조

`BossEncounterDirector`가 보스룸 전환 전체를 소유한다.

- `BossTeleportManager`: 진입 카운트다운, 안전 지점 텔레포트, 클라이언트 적용 완료 수집
- `BossEncounterDirector`: 참가자 집합, 연출 단계, 보스 스폰, 스킵 정족수, 전투 시작의 유일한 결정자
- `PlayerEncounterLock`: 플레이어 한 명의 연출 잠금·초기화·서버 거부 규칙
- `TwentyThreeIntroPresentation`: No.23의 연출용 낙하와 착지 애니메이션을 전투 공격 판정 없이 재생
- `BossEncounterHUD`: 로컬 대사와 ESC 안내·투표 수 표시
- `BossImpactFeedback`: 각 클라이언트의 카메라 흔들림과 로컬 착지 VFX
- `ChargeController`/`ChargingObject`: 서버 권한 충전기 패턴과 재사용

`BossTeleportManager`에 보스 스폰, UI, BT 시작까지 넣지 않는다. 텔레포트는 재사용 가능한 이동 책임으로 남기고, 보스전 수명 주기는 Director 한 곳에서만 전환한다.

## 4. 서버 상태 머신

| 단계 | 서버 작업 | 클라이언트 표현 | 종료 조건 |
|---|---|---|---|
| `Idle` | 진입 대기 | 기존 진입 패드 | 텔레포트 카운트다운 완료 |
| `AwaitingArrival` | 생존 참가자를 슬롯에 배정하고 도착 ACK 대기 | 대상 클라이언트가 위치·속도 적용 | 모든 유효 참가자 ACK 또는 연결 해제/사망으로 제외 |
| `Preparing` | 참가자 스냅샷, 연출 잠금, 전투 상태 초기화, No.23 상공 스폰, BT 닫힘 | 입력 정지, HUD 준비 | 필수 참조와 보스 스폰 성공 |
| `Descending` | 보스를 착지 지점까지 서버 이동 | JumpAttack 착지 모션 | 지면 높이 도달 |
| `Impact` | 착지 시각 확정 | 전 화면 shake, 로컬 VFX | 설정된 짧은 충격 유지 시간 만료 |
| `Dialogue` | 현재 페이지와 종료 시각 복제, ESC 투표 집계 | 대사 박스, 스킵 안내 | 마지막 페이지 종료 또는 만장일치 |
| `Combat` | 플레이어 잠금 해제, No.23 BT 시작 | HUD 제거, 조작 복구 | 보스전 종료 |
| `FailedSafe` | 보스 제거/참가자 해제 후 오류 기록 | HUD 제거, 조작 복구 | 재진입 가능 상태로 복귀 |

`Combat` 진입은 멱등적인 단일 메서드 `BeginCombatServer()`로만 수행한다. 정상 종료, 스킵, 중간 연결 해제, 연출 타임아웃 모두 이 메서드로 수렴한다.

## 5. 네트워크 권한과 복제

### 서버가 결정하는 값

- 연출 단계와 단계 시작 서버 시간
- 참가자 `ClientId` 집합
- 스킵 동의 `ClientId` 집합
- 현재 유효 인원과 동의 인원
- No.23 스폰과 위치
- 플레이어 연출 잠금 여부
- No.23 BT 활성화
- 충전기 활성 개수, 체력, 상승·하강 상태

### 클라이언트가 요청하는 값

- 자신의 텔레포트 적용 완료 ACK
- 자신의 ESC 스킵 동의 1회

서버는 요청자의 `ClientId`가 현재 유효 참가자에 포함될 때만 수락한다. 중복 ESC 요청은 한 표로 처리하며 취소 투표는 지원하지 않는다.

카메라 흔들림, HUD, 먼지 VFX는 게임 판정이 없는 로컬 표현이다. 서버가 확정한 단계·착지 이벤트를 받아 각 클라이언트가 재생하며 NetworkObject로 스폰하지 않는다.

## 6. 텔레포트와 겹침 방지

보스룸에 3개의 직렬화된 `PlayerArrivalPoint`를 둔다. 각 지점은 다음 조건을 만족해야 한다.

- 바닥 NavMesh 위
- 플레이어 캡슐 반경 두 배 이상 간격
- 투명 경계와 보스 착지 지점에서 충분히 이격
- 1~3인 모두 결정적인 `ClientId` 정렬 순서로 배정

`BossTeleportManager`는 대상별 RPC에서 위치, Rigidbody 속도, NetworkTransform을 적용한 뒤 서버에 encounter sequence ID가 포함된 ACK를 보낸다. 서버는 모든 현재 유효 참가자의 ACK를 받은 뒤에만 `BossEncounterDirector`에 완료 이벤트를 보낸다.

연결 해제 또는 사망으로 ACK 대상이 사라지면 즉시 대기 집합에서 제거한다. 남은 대상이 없으면 연출을 시작하지 않고 안전하게 `Idle`로 복귀한다. ACK에는 짧은 안전 타임아웃을 두되, 타임아웃 대상은 무시하고 전투를 강행하지 않고 `FailedSafe`로 복구한다.

## 7. 플레이어 잠금과 전투 상태 초기화

로컬 `PlayerInputReader.SetInputEnabled(false)`만으로는 이미 전송된 공격·스킬·피해 RPC를 막을 수 없다. 따라서 플레이어 프리팹에 서버가 소유하는 `PlayerEncounterLock`을 추가한다.

`BeginCinematicServer()`는 다음 순서로 실행한다.

1. 연출 잠금 값을 활성화한다.
2. 이동 속도와 Rigidbody 속도를 0으로 만든다.
3. 현재 기본 공격과 콤보 런타임을 취소한다.
4. 실행 중인 스킬을 `Cancelled` 사유로 종료한다.
5. `StatusEffectController.ClearAllServer()`로 버프·디버프를 모두 제거한다.
6. 플레이어 FSM을 연출 잠금 상태로 고정한다.
7. 오너 클라이언트의 일반 gameplay input을 끈다.

잠금 중에는 다음 서버 진입점이 요청을 거부한다.

- 이동 적용
- 기본 공격 시작·연계
- 스킬 시작·홀드
- 상태이상 적용
- `Player.ReceiveAttack`/`TakeDamage`

이 차단은 연출 시작 전에 날아온 지연 RPC에도 적용된다. ESC는 gameplay input action과 분리된 HUD 전용 입력 경로로 읽기 때문에 일반 입력을 꺼도 동작한다.

`EndCinematicServer()`는 상태와 속도를 다시 정리한 뒤 잠금 값을 해제하고, 오너 입력을 활성화한다. 사망·연결 해제된 플레이어에는 해제 RPC를 기다리지 않는다.

## 8. No.23 스폰과 착지 연출

기존 `TwentyThreeArenaContext.OnNetworkSpawn()`의 즉시 스폰과 즉시 `OpenBT()`는 제거하거나 Director가 호출하는 명시적 구성 메서드로 바꾼다. 보스 스폰 소유자는 반드시 `BossEncounterDirector` 하나여야 한다.

스폰 순서는 다음과 같다.

1. 서버가 보스룸 착지 지점 위 `introSpawnHeight`에 No.23 NetworkObject를 스폰한다.
2. `EnemyBTActivator`는 닫힌 상태를 유지한다.
3. `ChargeController`에 보스룸 충전기 4개를 등록한다.
4. `TwentyThreeIntroPresentation`이 기존 `JumpAttack`/`Leap` 착지 모션을 재생한다.
5. 서버가 보스 위치를 설정된 곡선과 시간으로 착지 지점까지 이동한다.
6. 지면 도달 시 정확한 착지 위치로 스냅하고 Impact 이벤트를 발생시킨다.

연출 중에는 `JumpController`의 전투용 범위 피해, 장판, 넉백 이벤트가 실행되지 않도록 cinematic guard를 둔다. 애니메이션 클립은 재사용하지만 전투 공격 판정은 재사용하지 않는다.

스킵이 낙하 중 발생하면 No.23을 즉시 착지 지점으로 스냅하고 연출용 공격 판정을 끈 다음 `BeginCombatServer()`로 전환한다.

## 9. 착지 피드백과 대사 UI

### 카메라 흔들림

프로젝트에 포함된 Cinemachine 3.1.6을 사용한다. 각 로컬 카메라에 impulse 수신 경로를 연결하고, 착지 이벤트에서 로컬 `CinemachineImpulseSource`를 한 번 발생시킨다.

강도와 지속 시간은 `BossImpactFeedback` 인스펙터 값으로 조정한다. 화면이 여러 개여도 각 클라이언트 자신의 플레이어 카메라만 흔든다.

### 착지 VFX

새 Asset Store 의존성을 추가하지 않는다. 기존 프로젝트의 연기·point 계열 VFX를 조합해 Git 소유 `BossLandingImpact.prefab`을 만든다.

- 낮고 넓게 퍼지는 먼지
- 바깥쪽으로 튀는 작은 돌 입자
- 짧은 수명
- 충돌 판정 없음
- 로컬 재생 후 자동 반환 또는 파괴

### 대사 UI

`BossEncounterHUD`는 화면 우측 중앙부터 하단까지 큰 네모 대사 패널을 표시한다. 페이지는 Director의 직렬화 목록으로 관리한다.

각 페이지 데이터:

- `text`
- `durationSeconds`

첫 페이지는 `보스 등장.`으로 저장한다. 이후 페이지는 인스펙터에서 순서대로 추가한다. 페이지가 바뀔 때 서버의 page index와 종료 시각을 기준으로 모든 클라이언트가 같은 내용을 표시한다.

## 10. ESC 스킵 정족수

연출 시작 시의 생존·도착 완료·연결 상태인 참가자를 최초 집합으로 잡는다.

- 1인: `ESC 건너뛰기`, 분수 미표시
- 2인: `ESC 건너뛰기 0/2`부터 시작
- 3인: `ESC 건너뛰기 0/3`부터 시작
- 한 참가자가 ESC를 누르면 `1/N`처럼 즉시 갱신
- 모든 현재 유효 참가자가 동의하면 즉시 전투 시작

연출 중 사망하거나 연결이 끊긴 참가자는 유효 집합과 동의 집합에서 즉시 제거한다. 제거 직후 `votes == eligible`이면 바로 스킵이 성립한다. 유효 참가자가 0명이 되면 No.23을 전투 상태로 풀지 않고 encounter를 안전 종료한다.

후발 접속자는 진행 중 연출의 정족수에 추가하지 않는다.

## 11. 충전기 4개

SVN 소유 `Env_Mv_bosscharger_upper.fbx`와 `.meta`는 수정하지 않는다. Git 소유 보스룸 프리팹에서 각 메시를 `ChargingObject` 네트워크 피격 오브젝트의 시각 자식으로 사용한다.

각 충전기는 다음 두 위치를 로컬 좌표로 저장한다.

- `hiddenLocalPosition`: 메시와 콜라이더가 바닥 아래 완전히 숨은 위치
- `activeLocalPosition`: 현재 의도한 지면 위 위치

초기 상태는 hidden이며 콜라이더와 피격이 꺼져 있다. 패턴 시작 시 서버가 현재 생존 플레이어 수에 맞는 개수만 선택해 올리고, 상승을 시작하는 순간부터 콜라이더와 피격을 허용한다.

파괴 시:

1. 해당 패턴의 파괴 수를 1회만 증가시킨다.
2. 콜라이더와 피격을 끈다.
3. hidden 위치로 내려간다.
4. 다음 `StartCharge`에서 체력과 이벤트 상태를 초기화해 재사용한다.

패턴 강제 종료 시에도 활성·상승 중인 모든 충전기를 hidden으로 내린다. `ChargeController.SetList()`는 중복 이벤트 구독을 제거한 뒤 다시 등록할 수 있어야 한다.

## 12. 보스룸 충돌과 NavMesh

`bossroom.prefab`에 다음 구조를 둔다.

- `BossFloorCollider`: 실제 바닥을 덮는 walkable collider
- `InvisibleBoundaries`: 네 방향과 필요한 틈을 막는 BoxCollider 집합
- `PlayerArrivalPoints`: 최대 3개
- `BossLandingPoint`
- `ChargeSockets`: 4개

투명벽은 렌더러 없이 충돌만 하며 `Wall` 레이어를 사용한다. Physics Layer Collision Matrix에서 Player와 Boss가 Wall에 충돌하는지 확인한다.

`MapNavMeshBaker`는 인스펙터의 walkable layer mask를 사용하고 Awake에서 임의로 Default 하나로 덮어쓰지 않는다.

- 바닥 collider: walkable mask 포함
- 투명벽과 장식 벽: `Wall` 레이어로 분리해 walkable mask에서 제외
- 낭떠러지와 보스룸 외부: surface가 생성되지 않음
- 보스 착지점과 플레이어 도착점: `NavMesh.SamplePosition` 성공

런타임 맵 생성 완료 뒤 bossroom까지 같은 `NavMeshSurface`에 포함해 빌드한다. 베이크 후 No.23의 `NavMeshAgent`를 착지점에서 Warp하여 전투 시작 전에 `isOnNavMesh == true`를 보장한다.

## 15. 수용 기준

- 1·2·3인 모두 서로 겹치지 않고 보스룸 바닥에 도착한다.
- 마지막 도착 ACK 전에는 보스 연출이 시작되지 않는다.
- 연출 중 이동, 공격, 스킬, 지속 피해, 새 상태이상, 콤보가 동작하지 않는다.
- 시작 시 기존 버프·디버프와 진행 중 공격·스킬·콤보가 제거된다.
- No.23은 상공에서 JumpAttack 모션으로 내려오며 착지 전 BT가 돌지 않는다.
- 착지 시 각 플레이어 화면에 shake와 먼지·돌 VFX가 한 번만 보인다.
- 첫 대사는 `보스 등장.`이고 후속 페이지를 인스펙터에서 추가할 수 있다.
- 1인은 분수 없이, 2·3인은 정확한 `동의/유효` 분수를 표시한다.
- 사망·연결 해제 인원은 즉시 분모에서 빠지고 남은 전원이 동의하면 스킵된다.
- 정상 종료와 스킵 모두 모든 생존 플레이어 입력과 보스 BT가 동시에 활성화된다.
- 플레이어가 보스룸 어느 경계에서도 떨어지지 않는다.
- No.23이 벽 바깥을 NavMesh 경로로 선택하지 않고 방 안에서 이동한다.
- 충전기는 평상시 완전히 바닥 아래에 있고, 패턴 때만 올라와 피격되며 파괴/종료 후 내려가 두 번째 패턴에서도 재사용된다.

## 16. 검증 시나리오

1. Unity 6000.3.16f1에서 컴파일 오류·경고 증가가 없는지 확인한다.
2. MPPM 1인에서 자동 연출 완료와 단독 ESC 즉시 스킵을 각각 확인한다.
3. MPPM 2인에서 `0/2 → 1/2 → 2/2`와 전원 입력 동시 복구를 확인한다.
4. MPPM 3인에서 산개 위치, `0/3 → 3/3`, 전 화면 착지 효과를 확인한다.
5. 3인 연출 중 한 명 연결 해제 후 분모 감소와 남은 만장일치 처리를 확인한다.
6. 연출 직전 지속 피해·버프·디버프·콤보·홀드 스킬을 만든 뒤 모두 초기화되고 HP가 더 감소하지 않는지 확인한다.
7. 정상 종료와 낙하 중 스킵 각각에서 No.23이 착지점 NavMesh 위에 있고 BT가 한 번만 시작하는지 확인한다.
8. 충전 패턴을 두 번 실행해 4개 중 인원수 설정만 활성화되고 파괴·종료 후 모두 숨는지 확인한다.
9. 플레이어 3명과 No.23을 보스룸 네 면과 모서리로 이동시켜 추락과 NavMesh 이탈이 없는지 확인한다.
