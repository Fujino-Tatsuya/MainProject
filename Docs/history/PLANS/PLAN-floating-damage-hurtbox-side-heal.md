# PLAN 268 — 플로팅 데미지: 판정 크기 배율·반대쪽 연출·외곽선 알파·힐 숫자

## 확정 사양
1. **판정(Hurtbox) 크기 배율**
   - 배율 = clamp(sqrt(대상 판정 크기 ÷ 기준 크기), 최소 0.8, 최대 1.6)
   - 기준 = 플레이어 판정 크기. 기존 구간 크기에 곱한다.
   - 카메라 줌과는 무관(지금처럼).
   - 기준·최소·최대는 `FloatingDamageSettings` 칸으로 둔다.
   - 판정 크기를 무엇으로 잴지(콜라이더 bounds 수평 크기·높이 등)는 레인이 정해 보고한다.
2. **맞은 반대쪽에 뜨기**
   - 좌우 판단: 화면 x 기준으로 공격자가 왼쪽이면 숫자는 오른쪽. 투사체는 공격자 본인 위치 기준.
   - 위치: 생성 위치를 반대쪽으로 약 40px 밀고, 뜨는 동안 같은 방향으로 약 30px 더 흘러간다.
   - 공격자가 없거나 거의 정면(장판·도트 등)이면 지금처럼 위로만 뜬다.
   - 누적 숫자는 처음 뜬 방향을 유지한다.
   - 거리·흐름·정면 판정 문턱은 SO 칸으로 둔다.
   - 공격자 정보가 각 피어에 이미 복제되는지 확인한다. 없으면 새 RPC 없이 가능한 방법을 찾고, 불가하면 보고한다.
3. **외곽선 알파**
   - `FloatingDamageSettings.outlineAlpha` 기본 0.8 칸을 추가한다(DigitSet 아님).
   - 팀원 스타일 최대 알파와 곱한다.
4. **힐 숫자**
   - 팀원 회복 시 피해 숫자와 같은 연출로 회복량을 띄운다. 색은 초록 계열.
   - 표시 필터는 피해 숫자와 같은 규칙(내 힐은 크게, 팀원끼리는 작고 흐리게).
   - 누적 합산·갱신은 피해 숫자와 같다. 회복량 0(풀피)은 숨긴다.
   - 대상은 모든 회복(회복 스킬·특성 회복·소생 등)이다.
   - 1·2를 힐에도 적용한다. 반대쪽 기준은 힐한 사람이고, 자기 회복은 위로만.
   - 회복 사건이 각 피어에 복제되는지 확인한다. 새 RPC 가 필요하면 먼저 보고한다.

## 작업 방식
- 브랜치: Work1 `feature/FloatingDamageHurtboxScaleSide` (최신 development 기준)
- 커밋 순서:
  1. 외곽선 알파
  2. 판정 크기 배율(순수 함수 + EditMode)
  3. 반대쪽 연출(순수 함수 + EditMode)
  4. 힐 숫자
  5. 디버그 씬 `DebugFloatingDamage` 에서 확인할 수 있게 + 문서
- 컴파일·EditMode 는 직접 돌린다. push·병합은 지시 후. 디버그 씬은 빌드 목록에 넣지 않는다.

## 검증(사용자 Play)
- 작은 몹·플레이어·보스 숫자 크기 차이가 0.8~1.6배 안에서 자연스러운지
- 왼쪽에서 때리면 오른쪽, 오른쪽에서 때리면 왼쪽에 뜨고 그쪽으로 흘러가는지. 장판·도트는 위로만.
- 외곽선이 80% 로 옅어졌는지, SO 값을 바꾸면 반영되는지
- 팀원 힐 시 초록 숫자가 뜨고 누적되는지, 풀피는 안 뜨는지, 팀원끼리 힐은 작고 흐린지
- 호스트·클라·관전 화면이 같은지
