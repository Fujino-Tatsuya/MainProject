# 룩 A/B 비교 & 조절 가이드 (아트용)

> 대상: 아트팀 · 렌더링 룩을 눈으로 보고 값을 조절하는 사람.
> 최종 갱신 2026-08-06 · 브랜치 `feature/maprendering` · 씬 `4.MapScene`
> 코드/설계 배경은 [PLAN-vision.md](../../PLAN-vision.md) §8. 이 문서는 **쓰는 법만** 다룬다.

---

## 1. 보는 방법

1. **`0.BootStrapScene` 부터 Play** 한다.
   🔴 `4.MapScene` 을 단독으로 Play 하면 **카메라가 안 뜬다**("No cameras rendering").
   맵 씬에는 카메라가 없고 런타임에 만들어지기 때문이다.
2. 게임 화면(Game 뷰)을 **한 번 클릭**해 포커스를 준다.
   포커스가 없으면 키 입력이 게임에 안 들어간다.
3. **F9** — 룩 A ↔ B 전환. 화면 위쪽에 지금 어느 룩인지 2.5초간 표시된다.
4. **F8** — 프레임/성능 HUD(선택).

> 판정은 **고정된 한 지점**에서 A/B 를 번갈아 찍어 비교한다.
> 매번 다른 위치를 찍으면 비교가 성립하지 않는다.

---

## 2. 두 룩의 차이

| | **룩 A** | **룩 B** |
|---|---|---|
| 화면 표시 | `LOOK A — 채도 살림 (디밍·차폐 없음)` | `LOOK B — 디밍 + 저채도 + 시야 차폐` |
| 배경 흐림(마스크 블러) | ✅ | ✅ |
| 픽셀레이트 | ✅ | ✅ |
| 전체 디밍 + 저채도 | ✗ | ✅ |
| 시야 차폐 (플레이어 주변만 밝음) | ✗ | ✅ |

**흐림과 픽셀레이트는 두 룩 공통이다.** F9 로 바뀌는 것은 **어두워지는가 / 시야가 막히는가** 뿐이다.
→ 흐림·픽셀을 조절하면 **A·B 양쪽이 같이 바뀐다.** 디밍·차폐를 조절하면 **B 만** 바뀐다.

⚠️ 룩 B 에서는 **멀리 있는 적이 안 보인다.** 결함이 아니라 시야 차폐의 의도된 결과다.

## 3. 조절 손잡이 — "이게 마음에 안 들면 여기"

### 3.1 흐림 · 픽셀레이트 (A·B 공통)

**파일: [`Assets/99.Settings/MaskBlurSettings.asset`](../../Assets/99.Settings/MaskBlurSettings.asset)**
(Project 창에서 클릭 → Inspector)

| 이게 마음에 안 들면 | 이 값 | 지금 | 방향 |
|---|---|---|---|
| 선명한 중앙이 너무 좁다/넓다 | `size` | (0.65, 0.34) | x=좌우, y=상하. 키우면 선명 영역이 넓어짐 |
| 픽셀 걸리는 영역이 너무 넓다 | **`pixelateRegionScale`** | **1.242** | **키우면 픽셀 영역만 좁아진다(흐림은 그대로)** |
| 픽셀이 너무 굵다/잘다 | **`pixelBlockSize`** | **8** | 픽셀 단위. 크면 굵다 (또렷한 레트로는 16~28) |
| 픽셀이 안 보인다 | `pixelBlockSize` ↑ 또는 `blurStrength` ↓ | — | **블러가 픽셀의 대비를 지운다** (§4 참조) |
| 플레이어까지 픽셀로 만들고 싶다 | `pixelateMode` | `OutsideOnly` | → `FullScreen` (이때 `pixelateRegionScale` 은 무시됨) |
| 픽셀레이트를 아예 끄고 비교하고 싶다 | `pixelateEnabled` | ✔ 켜짐 | 체크 해제 |
| 흐림이 약하다/세다 | `blurStrength` | 1 | 0~4 |
| 흐림 경계가 티난다 | `feather` | 0.35 | 키우면 경계가 부드러워짐 |
| 선명 영역 모양 (원 ↔ 둥근 사각) | `roundness` | 4 | 2=타원, 커지면 사각형에 가까워짐 |
| 배경만 채도를 빼고 싶다 | `desaturate` | 0 | 0~1 |
| 배경만 어둡게 하고 싶다 | `darken` | 0 | 0~1 (비네트와 겹치니 둘 중 하나만) |
| 흐림 전체를 끄고 싶다 | `enabled` | ✔ 켜짐 | 끄면 패스가 빠져 비용 0 |

## 4. 🔴 저장되는 값 / 사라지는 값

Play 중에 값을 돌려 찾는 게 가장 빠르지만, **남는 것과 사라지는 것이 다르다.**

| 무엇 | Play 중 조절하면 |
|---|---|
| `MaskBlurSettings.asset` | ✅ **남는다** (애셋이라 Play 를 끝내도 유지) |
| `FogProfile.asset` | ✅ **남는다** |
| `Global Volume Profile.asset` | ✅ **남는다** |
| 씬의 `FogManager` (`losMaxDist` 등) | ❌ **사라진다** — Play 종료 시 원래대로 |
| 씬의 `LookToggle` 설정 | ❌ **사라진다** |

→ 씬 오브젝트 값은 **Play 중에 찾은 숫자를 메모해 두고, Play 를 끝낸 뒤 다시 입력**해야 한다.

### 왜 픽셀이 안 보일 때가 있나

**블러가 픽셀레이트가 먹을 대비를 미리 지운다.** 흐려진 그림은 인접 픽셀의 색 차이가 없어서,
잘게 자르면 블록 경계에 아무 대비도 안 남는다 — 그냥 흐릿하게만 보인다.
그래서 **블록이 흐림 반경보다 확실히 커야** 픽셀로 읽힌다.

> 안 보이면 순서대로: `pixelBlockSize` 올리기 → `blurStrength` 내리기 → `downsampleShift` 0 으로.

## 5. 건드리지 말 것

- **`downsampleShift`** (지금 1) — 흐림을 계산하는 해상도다. 0 으로 내리면 비용이 4배가 된다.
  성능이 남을 때만, 팀장 확인 후.
- **`matchAspect`** (켜짐) — 끄면 해상도·화면비가 바뀔 때 선명 영역 모양이 변한다.
- **`maskTexture`** (비어 있음) — 넣으면 `pixelateRegionScale` 이 안 먹고 픽셀 영역이 흐림 영역과
  같아진다. 그리고 빌드에서 누락될 수 있어 확인이 필요하다.
- **벽이 반투명해질 때 보이는 점무늬(디더)** — 품질 결함이 아니라 **의도된 비용 절충**이다.
  끄면 벽 뒤 플레이어가 아예 안 보인다.
- **`WallOcclusionSettings` 의 `animateDither`** — 현재 안티에일리어싱(SMAA)과 맞지 않는다. 끈 채로 둘 것.

## 6. 룩이 확정되면

`LookToggle` 은 **판정 도구지 결과물이 아니다.** A/B 중 하나가 확정되면 팀장이:

1. 이긴 룩의 값을 기본값으로 커밋하고,
2. 씬에서 `LookToggle` 컴포넌트와 스크립트를 **삭제**한다.
   (위치: `4.MapScene` → Hierarchy 의 **`MaskBlurController`** 오브젝트에 붙어 있다.
   여기서 토글 키와 시작 룩도 바꿀 수 있다.)
   (`ProfilerHUD` 도 같다 — 제출 빌드 전에 씬에서 빼야 missing script 경고가 안 난다.)

확정 의견을 줄 때는 **어느 룩 + 바꾸고 싶은 값**을 같이 적어 주면 그대로 반영된다.
예: "B 로 가되 `losMaxDist` 6, `pixelBlockSize` 12".

## 7. 배경 흐림은 왜 DoF 가 아니라 마스크 블러인가

아트가 "배경 흐림"을 찾을 때 **DoF(Depth of Field)를 먼저 볼 가능성이 높으므로** 적어 둔다.
2026-08-06 부터 볼륨 프로파일의 **Depth of Field 는 꺼져 있고, 다시 켜면 안 된다.**

### DoF 로는 원하는 그림이 안 나온다

DoF 는 **깊이(카메라로부터의 거리)** 로만 흐림을 판단한다. 우리 화면은 **탑다운 쿼터뷰에
고정**이라, 화면 좌우 외곽은 중앙과 **깊이가 거의 같다.**

→ DoF 를 켜면 흐려지는 건 "화면 아래(가까움) / 화면 위(멂)"뿐이고,
**좌우 외곽은 절대 흐려지지 않는다.** 우리가 원하는 것은 "플레이어 주변만 선명"이므로
필요한 판단 기준은 깊이가 아니라 **화면 위치**다.

그래서 **화면 좌표로 선명 영역을 직접 지정하는** 마스크 블러를 따로 만들었다
(`MaskBlurSettings` 의 `center` · `size`). 카메라가 플레이어를 따라가므로 화면 중앙 = 플레이어이고,
결과적으로 플레이어를 따라다니는 효과가 된다.

### 둘을 같이 켜면 생기는 문제

| 문제 | 왜 |
|---|---|
| 흐림이 두 겹으로 걸린다 | 같은 화면에 DoF 흐림 + 마스크 블러가 순서대로 적용된다 |
| 튜닝이 안 잡힌다 | `blurStrength` 를 내려도 DoF 쪽 흐림이 남아 "값을 줬는데 안 변한다"가 된다 |
| 원인 추적이 어려워진다 | 흐림의 출처가 두 곳이라 어느 값이 범인인지 갈라내야 한다 |
| 공짜가 아니다 | DoF 도 풀스크린 패스다. 겹쳐 봤자 얻는 게 없다 |

DoF 항목 자체는 **삭제하지 않고 비활성(체크 해제)으로 남겼다** — 튜닝값
(Gaussian 26~50m, focusDistance 19.7)이 남아 있어 나중에 컷신처럼 카메라가 움직이는
연출에서 필요해지면 되살릴 수 있다. **인게임 탑다운 화면에서는 켜지 않는다.**

> 한 줄 요약: **깊이로 판단하는 흐림(DoF)은 탑다운에서 좌우를 흐릴 수 없다.
> 그래서 화면 위치로 판단하는 마스크 블러를 쓴다. 배경 흐림 손잡이는 §3.1 하나뿐이다.**
