## 1. 핵심 요약

Project MT는 2026년 5월 기존 익스트랙션 방향에서 **노드 기반 탑다운 협동 액션 로그라이트**로 변경되었다. 7월 개발의 핵심은 콘텐츠 수를 늘리는 것이 아니라 다음 과정을 실제 플레이 가능한 하나의 수직 슬라이스로 연결하는 것이다.

> **Title → Lobby → 캐릭터·룬 선택 → Stage → Boss → Result → Lobby 복귀**

맵은 절차적으로 생성되는 Stage 구역 10개와 별도 Boss Room 1개로 구성한다.

| 구역 | 개수 |
|---|---:|
| Large | 3 |
| Medium | 4 |
| Small | 3 |
| Boss Room | 1 |
| **합계** | **11** |

현재 코드에는 근접 플레이어의 이동, 데이터 기반 4타 기본 공격, 상태 처리와 보스 주요 패턴이 들어가 있다. 그러나 스킬 3종, 인터럽트 결과 처리, Groggy 연동, 일부 네트워크 동기화와 보스 기믹 연결은 아직 완성되지 않았다.

따라서 현재 상태는 **주요 전투 기능의 구현물은 존재하지만 전체 통합 및 플레이 검증이 필요한 단계**이다.

## 2. 프로젝트 방향과 핵심 재미

| 항목 | 확정 내용 |
|---|---|
| 장르 | 노드 기반 탑다운 협동 액션 로그라이트 |
| 플레이 인원 | 1~3인 |
| 네트워크 | Listen Server 기반 |
| 맵 | 부분 절차 생성형 노드 맵 |
| 전투 중심 | 패턴 인지와 대응 선택 |
| 7월 목표 | 웰즈·23호 보스 전투 수직 슬라이스 |

기획상 핵심 전투 재미는 다음 흐름으로 정의된다.

1. 몬스터의 공격 전조와 패턴을 확인한다.
2. 기본 공격과 특수 공격을 구분한다.
3. 공격, 회피, 인터럽트 중 적절한 대응을 선택한다.
4. 인터럽트 성공으로 몬스터를 Groggy 상태로 만든다.
5. Groggy를 누적해 Break 상태를 유도한다.
6. 최대 3명의 플레이어가 취약 시간에 공격을 연계한다.

단순히 공격력으로 적을 처치하는 구조가 아니라, **패턴을 읽고 끊을 공격과 피할 공격을 판단하는 것**이 핵심 재미다.

## 3. 목표 게임 플레이 루프

### 3.1 Title

- Host 시작 및 Client 접속
- IP와 Port 입력
- 닉네임 입력
- 설정 화면
- 공모전 버전에서는 계정 기능 없이 닉네임만 사용

### 3.2 Lobby

- 최대 3인 접속 및 고정 3개 플레이어 슬롯
- 접속자 닉네임 표시
- 캐릭터와 룬 또는 빌드 선택
- Ready 및 설정 버튼
- 전원 Ready 시 게임 시작
- Ready 이후 캐릭터와 빌드 변경 제한

최신 회의 기준으로 Lobby는 미완성이며, 근접 플레이어 스킬 및 몬스터 상호작용과 함께 최우선 작업으로 분류되어 있다.

### 3.3 Game Init 및 Loading

- Host에서 맵 Seed 결정
- Stage 구역 10개 배치
- 맵 생성 결과와 미니맵 동기화
- 플레이어 및 일반 몬스터 Spawn
- 로딩 화면 디밍
- Host와 Client의 초기 상태 동기화

### 3.4 Stage 및 Boss

- 일반 근접 몬스터 전투
- 노드 이동 및 전투 구역 진입
- 보스 진입 조건 달성
- 별도 Boss Room 이동
- 웰즈·23호 보스 전투
- 보스 처치 또는 플레이어 전멸 판정

### 3.5 Result 및 Lobby 복귀

- 개인별 전투 기여 정보
- 획득 재화와 보상
- 경험치 또는 성장 결과
- 결과 확인 후 Lobby 복귀
- 다음 세션 재시작

기획 문서상 결과는 개인 단위로 계산하며 팀 합산 기여도는 별도로 추적하지 않는다.

## 4. 플레이어 개발 현황

`origin/feature/Player`는 `origin/feature/Wells&No.23`를 병합한 브랜치이므로 플레이어와 보스 구현을 모두 포함한다.

### 4.1 실제 구현이 확인된 기능

- Rigidbody 기반 이동과 회전
- Idle, Move, Attack, Interrupt 상태
- Grabbed, Knockback, Dead 상태
- 상태이상에 따른 행동 제한
- 데이터 기반 4타 기본 공격
- 애니메이션 이벤트 기반 타격 판정
- Overlap, Projectile, Raycast 공격 방식
- 기본 공격 Server 승인 RPC
- 잡기와 넉백의 Owner 전달 구조

기본 공격은 컨트롤러, 데이터, 타격 판정으로 분리되어 있다. 4타 콤보와 마지막 공격 1.2배 배율도 데이터로 관리된다.

### 4.2 아직 확인되지 않은 기능

- 근접 캐릭터 스킬 3종
- 패링과 대시 무적
- 궁극기
- 원거리 캐릭터 전용 스택 및 Q/E/R
- 완성된 Ability 실행 시스템

현재 `CharacterDefinition`은 캐릭터 ID, 외형, Animator, 기본 공격 데이터와 기본 스탯만 보유하며 캐릭터별 스킬 슬롯은 대부분 TBD 상태다.

### 4.3 인터럽트 구현 상태

플레이어가 짧게 전진하며 인터럽트 애니메이션을 실행하는 상태는 존재한다. 그러나 다음 결과 처리는 코드에서 확인되지 않았다.

- 적 공격 패턴 취소
- 적 공격 판정 제거
- Groggy Count 증가
- Groggy 또는 Break 전환

따라서 현재 인터럽트는 **플레이어 동작은 구현되어 있지만 전투 시스템 전체와의 연동은 미완성**이다.

## 5. 웰즈·23호 보스

### 5.1 구성과 권한

- **23호**: 근접 전투를 담당하는 대형 로봇 본체
- **웰즈**: 23호 상부에 탑승해 폭탄과 보조 공격 담당
- **권한**: 보스 AI, 이동, 피해, 패턴, 장판은 Server 권한

보스 AI는 Unity Behavior Graph와 Blackboard 기반이며 Behavior Graph와 NavMeshAgent는 Server에서만 활성화된다.

### 5.2 기본 및 접근 패턴

| 패턴 | 기획 내용 | 코드 상태 |
|---|---|---|
| Hook Attack | 좌·우 훅 독립 단타 | 상태 및 선택 구조 존재 |
| Upper Attack | 어퍼컷 및 공중 상태 부여 | 상태 존재 |
| Grab | 잡기 → 지속 피해 → 던지기 | 컨트롤러 존재 |
| Jump Attack | 대상 위치 점프 및 착지 AoE | 서버 판정·예고 RPC 존재 |
| Dash Attack | 대상 방향 돌진 및 경로 타격 | 상태 및 컨트롤러 존재 |

공격 선택은 대상과의 거리 및 공격별 가중치를 기준으로 후보를 구성한 후 결정한다.

### 5.3 폭탄 기믹

- 웰즈가 폭탄을 투척한다.
- 플레이어 기본 공격으로 폭탄을 반사한다.
- 공격 피해량에 따라 비행 거리가 결정된다.
- 비행 중 추가 공격은 무시한다.
- 벽, 플레이어 또는 보스 충돌 시 폭발한다.
- 폭발 위치에 화염 장판을 생성한다.
- 장판이 중첩되면 범위가 증가한다.
- 보스에게 반사하면 보스 공격 취소와 피해를 유도한다.

현재 코드에는 폭탄 생성, 포물선 이동, 타이머, 충돌, 피해, 장판 생성·확대, Client 시각 동기화가 존재한다. 다만 플레이어 기본 공격과 폭탄 반사 판정의 통합 흔적이 혼재되어 있어 실제 플레이 검증이 필요하다.

### 5.4 송전기 및 차징

- 플레이 인원에 따라 활성화해야 하는 송전기 수가 달라진다.
- 보스는 중앙에서 차징한다.
- 차징 중 보스 실드가 회복된다.
- 근접 플레이어에게 지속 피해와 밀치기를 준다.
- 제한시간 내 송전기를 해제하면 보스가 Groggy 상태가 된다.
- 실패하면 Rage 상태로 전환된다.

`ChargeController`에는 인원수 기반 활성 수 설정과 Client 표시 동기화가 존재한다. 그러나 Boss Room에서 송전기 목록을 전달하는 부분이 주석 처리되어 있어 현재 기믹 연결이 끊어졌을 가능성이 높다.

### 5.5 페이즈

| 페이즈 | 체력 구간 |
|---|---|
| 1페이즈 | 100~66% |
| 2페이즈 | 66~33% |
| 3페이즈 | 33% 이하 |

페이즈 전환 시 현재 행동을 완료한 후 송전기·차징 패턴에 진입하는 것이 기획이다. 상태와 Behavior Graph 에셋은 존재하지만 실제 HP 임계값 전환은 Unity 실행 검증이 필요하다.

## 6. 일반 몬스터

### 6.1 일반 근접 몬스터

## 7. 성장 및 보상 시스템

| 구분 | 의미 |
|---|---|
| 룬 | 게임 시작 전에 선택하는 지속형 어빌리티 |
| 특성 | 한 세션 안에서 획득하는 휘발성 어빌리티 |
| 인게임 재화 | 상점, 특성, 강화, 스탯 구매 |
| 시스템 재화 | 룬 개방 및 강화 |

최신 면담 메모의 7월 알파 보상 요구사항은 재화, 경험치, 노드 키, 노드 개방 테스트, 전투 결과 표시다.

다만 기존 기획 문서에는 **7월 수직 슬라이스에서 인게임 레벨과 경험치를 제외한다**는 내용이 있다. 따라서 재화·경험치·노드 키는 이번 면담에서 추가된 신규 요구사항으로 분류하고 기존 정본의 갱신 여부를 결정해야 한다.

노드와 상호작용하여 전투 보상을 선택·획득하는 완성형 시스템은 8월 말~9월 초 목표로 분리한다.

## 10. 면담 피드백

- 콘텐츠 확장보다 한 세션이 끝까지 작동하는 수직 슬라이스를 우선한다.
- Stage 구역 10개와 Boss Room 1개를 연결한다.
- 근접 캐릭터 조작과 기본 공격 완성도를 우선한다.
- 인터럽트, Groggy, Break와 협동 연계를 핵심 재미로 검증한다.
- 일반 근접 몬스터와 보스 전투를 우선 완성한다.
- 원거리 몬스터와 원거리 플레이어는 후순위로 조정한다.
- 7월 24일까지 플레이 가능한 내부 버전을 만든다.
- 7월 27일 제출 버전을 완성한다.
- 수직 슬라이스 완료 후 코드 구조와 시스템을 정비한다.
- 기존 보스 구현과 새 통합 구현의 차이를 비교 보고서로 작성한다.

## 11. 지시사항

1. Title부터 Result, Lobby 복귀까지 전체 플레이 루프를 연결한다.
2. 최대 3인 Lobby와 Ready 흐름을 완성한다.
3. 근접 캐릭터의 기본 공격, 인터럽트, 스킬 3종을 완성한다.
4. 일반 근접 몬스터와 웰즈·23호 보스 전투를 통합한다.
5. 원거리 일반 몬스터는 현재 제출 범위에서 제외한다.
6. 송전기, 폭탄, 잡기, 차징과 보스 페이즈를 실제 플레이로 검증한다.
7. 전투 종료 후 최소 결과 보고와 보상 표시를 구현한다.
8. 일반 몬스터와 보스 AI 구조를 정리한다.
9. 기존 보스 구현과 새로운 통합 구현의 차이를 보고서로 작성한다.
10. Host와 Client에서 동일한 전투 결과가 나오는지 MPPM으로 확인한다.

## 12. 기존 보스 구현과 플레이어·통합 구현 비교

> Git 계정과 실제 담당자 이름의 정확한 매핑은 별도 확인이 필요하다.

| 비교 항목 | 기존 보스 구현 | 플레이어·통합 구현 |
|---|---|---|
| 중심 구조 | Behavior Graph와 Blackboard | Player FSM과 데이터 기반 공격 |
| 주요 범위 | 보스 패턴과 기믹 | 이동, 상태, 평타, 네트워크 승인 |
| 권한 | Server 중심 AI | Owner 입력 → Server 판정 |
| 공격 | Hook, Grab, Jump, Dash, Bomb | 4타 콤보와 다양한 판정 방식 |
| 상태 | Charging, Rage, Groggy, Break | Attack, Interrupt, Grabbed, Knockback |
| 주요 통합점 | 보스가 플레이어에게 상태 적용 | 플레이어가 공격·인터럽트를 보스에 적용 |
| 현재 문제 | 송전기·페이즈 검증 | 스킬·인터럽트 결과 미완성 |
| 공통 문제 | 피해 정보, 잡기, 그로기, 네트워크 경계 연결 | 피해 정보, 잡기, 그로기, 네트워크 경계 연결 |

비교의 목적은 우열 판단이 아니라 다음 사항을 확인하는 것이다.

- 두 구조가 어떤 책임을 맡았는가
- 통합 과정에서 어떤 계약이 충돌했는가
- 다음 구현에서 공통 인터페이스를 어떻게 정의해야 하는가
