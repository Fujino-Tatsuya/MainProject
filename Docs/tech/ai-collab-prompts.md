# AI 협업 프롬프트 템플릿 (복붙용)

> 출처: Claude Code 개발자의 협업 기법 (https://youtu.be/vZaG9KlT-40)
> Claude Code에서는 이 기법들이 [AIRULE.md](../../AIRULE.md) 규칙으로 자동 적용된다.
> 이 문서는 **다른 AI 도구(Codex, 웹 챗 등)를 쓰거나 규칙이 안 먹는 상황**에서 복사해 쓰는 원문 템플릿.

## 1. 작업 시작 전 — '모르는 것' 찾아내기

### 기법 1: 사각지대 점검 (지시하기 전에 구조 파악) → AIRULE "Blind-Spot Briefing"

```
나는 지금 이 프로젝트에서 [여기에 목표 기능 입력]을 구현하려고 해. 하지만 내가 이 환경의
아키텍처나 의존성에 대해 모르는 부분이 있을 수 있어. 코드를 바로 짜지 말고, 내가 놓치고
있거나 모르는지도 모르는 '사각지대(위험 요소, 예외 처리 등)'를 먼저 점검해서 알려줘.
내가 너에게 더 정확한 지시를 내릴 수 있도록 도와줘.
```

### 기법 2: 프로토타입 제시 (설계가 막막할 때) → AIRULE "Blind-Spot Briefing" 2문단

```
이 기능에 대한 완벽한 설계 스펙을 지금 말로 다 설명하기 어려워. 코드를 바로 작성하지 말고,
이 문제를 해결할 수 있는 완전히 다른 접근 방식이나 구조(프로토타입)를 3가지 정도 먼저 제안해 줘.
각 방식의 장단점을 간단히 보여주면 내가 그중 하나를 선택할게.
```

### 기법 3: 역질문 인터뷰 (방향을 정한 후 구체화) → AIRULE "Grill Workflow"

```
이제 [선택한 방법]으로 개발을 진행할 거야. 코드를 작성하기 전에, 내 요구사항 중에서 애매하거나
논리적인 빈틈이 있는 부분을 나에게 취조하듯이 물어봐 줘. 한 번에 여러 개 묻지 말고 반드시
한 번에 하나씩만 질문해. 내 대답에 따라 다음 질문이나 설계를 조정해 줘.
```

## 2. 작업 진행 중 — 멈추지 않고 완성도 높이기

### 기법 4: 레퍼런스 활용 (원하는 동작이 명확할 때) → AIRULE "Reference-Based Implementation"

```
[참고할 파일이나 코드 텍스트 첨부] 이 코드가 내가 원하는 동작과 가장 똑같이 작동해.
이 코드를 깊이 분석한 뒤, 이와 똑같은 논리와 의미를 유지하면서 우리 프로젝트의 언어와
환경([예: C#, Unity URP 등])에 맞춰서 완벽하게 다시 구현해 줘.
```

### 기법 5: 구현 노트 작성 (AI의 짐작을 통제) → AIRULE "Implementation Rules" deviation log

```
이제 앞서 합의한 내용대로 코드를 작성해 줘. 단, 작업을 진행하면서 원래 계획에서 벗어나야
하는 상황이나 예상치 못한 문제(의존성 충돌 등)를 만나면, 더 안전하고 보수적인 방법을 선택해.
그리고 그 이탈 사항과 선택한 이유를 'IMPLEMENTATION_NOTES.md'라는 파일에 꼼꼼히 기록하면서
멈추지 말고 끝까지 완성해.
```

## 3. 작업 완료 후 — 온전히 내 것으로 만들기

### 기법 6: 퀴즈 및 검증 (코드를 완전히 장악) → AIRULE "Ownership Quiz" + `/diff-check`

```
작업이 끝났어. 내가 이번에 네가 작성한 코드와 변경 사항을 완벽하게 이해하고 통제할 수 있어야 해.
전체적인 변경 사항에 대한 요약 보고서를 작성해 주고, 마지막에 내가 이 코드를 제대로 이해했는지
스스로 테스트해 볼 수 있는 객관식 또는 단답형 퀴즈를 3개 내 줘.
```

> 일상적으로는 `/diff-check`가 그날 diff에서 이해도 체크리스트+퀴즈를 자동 생성한다 (Docs/tech/diff-check-design.md).
