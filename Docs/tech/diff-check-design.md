# /diff-check 설계 (Phase D — 안개구역 체크리스트)

> 목적: AI가 짜준(또는 본인이 짠) 코드의 diff에서 개발자가 이해·검증하지 못하고 넘어간 부분(안개구역)을
> 오픈북 체크리스트로 만들어, 시간 날 때마다 체크해가며 해소하게 한다. 프로그래머 전용.
> 기반: [knowledge-base-vault-design.md](knowledge-base-vault-design.md) Phase D 항목. 2026-07-07 합의.

## 형태와 위치

- **커맨드**: MainProject 레포 `.claude/commands/diff-check.md` (git 커밋 → 프로그래머 팀원 전원 사용).
- **출력**: Vault `Worklog/<이름>/안개체크 YYYY-MM-DD.md` — Obsidian 체크박스(`- [ ]`)라서
  체크 상태가 파일에 영구 저장되고 Syncthing으로 백업된다. (HTML+localStorage 안은 체크 기록이
  브라우저에 종속돼 장기 추적 목적과 상충하여 기각.)
- 실행자 이름은 git `user.name` → AGENTS.md 분담표 매칭으로 추론, 애매하면 사용자에게 확인.
- 기획·아트는 대상 아님 — 프로그래머 외 폴더는 만들지 않는다.

## 동작 흐름

```
/diff-check              → 오늘 내 커밋 + 미커밋 변경 (기본, 매일 마무리 루틴)
/diff-check development  → development 대비 현재 브랜치 전체 (PR 전 점검)
/diff-check <ref>        → 해당 ref 대비 diff
```

1. diff 범위 확정 → 변경 파일별로 실제 코드 읽기 (diff 헝크만이 아니라 맥락 포함)
2. 규칙 문서 대조: `Docs/tech/architecture.md` · `networking.md` · `conventions.md` + AGENTS.md 코어 설계 원칙
   (UnitBase 최소화·컴포넌트 조립 / 네트워크 권한: 플레이어=클라·보스·데미지·상태이상·장판=서버 / SO 데이터 주도)
3. 체크리스트 3섹션 생성:
   - **✅ 검증 체크** — "실제로 돌려서 확인했는가". 변경 특성 기반 구체 항목
     (예: 네트워크 코드면 "MPPM 2인으로 호스트/클라 양쪽에서 확인했는가").
   - **🧠 이해도 체크 (오픈북)** — "이 로직을 설명할 수 있는가" 질문. 모든 항목에 `파일:라인` 표기 →
     코드를 열어 읽고(오픈북) 이해되면 체크.
   - **⚠️ 규칙 대조 의심 지점** — 설계원칙·권한 규칙과 어긋나 보이는 부분. 확신 없으면 단정 대신 질문형.
4. 같은 날 재실행 시 기존 파일을 읽고 이미 있는 항목은 중복 생성하지 않으며 새 변경분만 추가.
5. 파일 상단에 "어제까지 미해소 N건 (파일 링크)" 한 줄 요약 이월 표시 (항목 복사는 안 함).

## 품질 원칙

- **evidence-only**: 이 diff의 구체 지점을 가리키는 항목만. 일반론("null 체크 했나요?") 금지.
- **회당 최대 12개** — 많으면 체크를 포기하게 된다. 우선순위: 네트워크 권한 > 코어 설계 원칙 > 검증 > 컨벤션.
- 원본에 없는 내용 지어내지 않기 (Vault 파이프라인 공통 원칙).

## /daily-todo 연동

`/daily-todo`(Vault `.claude/commands/daily-todo.md`, Phase B)가 대상 팀원이 **프로그래머**이면
`Worklog/<이름>/안개체크 *.md`에서 미체크(`- [ ]`) 항목을 집계해 오늘의 할일에
"🌫️ 안개구역 미해소 N건" 섹션(상위 몇 개 미리보기 + 파일 링크)으로 포함한다.
기획·아트 팀원의 todo에는 이 섹션을 넣지 않는다.

## 범위 밖

- HTML 뷰 생성 (Obsidian 체크박스로 충분해지지 않을 때 재검토)
- 해소율 통계/대시보드
- PR 자동 코멘트 (팀장 리뷰 보조는 별도 논의)
