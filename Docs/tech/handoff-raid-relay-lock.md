# 요청 — 레이드 '간파 릴레이' 우클릭 쿨 반환·잠금 (경석 → 은희, 2026-10-20)

> 보스 쪽 계획: [PLAN-boss-raid-relay.md](../../PLAN-boss-raid-relay.md) · 기획 원문 SVN r475 `Re_C_보스_기믹1_간파릴레이_예외처리_20261020.md` §3-4·3-5·4-2.
> 보스 쪽(판정·잠긴 사람 간파 불인정)은 경석이 만든다. **플레이어 쪽 두 가지만** 부탁한다.

## 보스가 보내는 신호 (전 피어, 서버 확정 후 RPC)
| 이벤트 | 인자 | 뜻 |
|---|---|---|
| `TwentyThreeBoss.RelayCounterAccepted` | `ulong clientId` | 이 사람의 간파가 릴레이 성공으로 **인정됨**(돌진 시도당 1명) |
| `TwentyThreeBoss.RelayLockChanged` | `ulong clientId, bool locked` | 이 사람의 우클릭이 이번 라운드 잠김(true) / 풀림(false) |
| `TwentyThreeBoss.RelayEnded` | — | 기믹 종료(성공·실패·중단 공통) — 남은 잠금 전부 해제 |

정적 이벤트(`static event Action<...>`)로 낼 예정. 이름·형태가 불편하면 말해 주면 맞춘다.

## 부탁하는 것
1. **쿨 반환**: `RelayCounterAccepted(내 clientId)` 를 받으면 내 우클릭(간파 스킬) **남은 쿨을 0** 으로.
   - ⚠️ 우클릭 동작 종료 콜백이 쿨을 다시 세팅하지 않게(문서 4-2). 이번 사용분만 반환, 다음 사용의 쿨은 정상.
2. **잠금**: `RelayLockChanged(내 clientId, true)` 동안 우클릭 **사용 불가** + 아이콘에 잠금 표시(쿨 원형과 구분, 문구 "동료 차례"). false 또는 `RelayEnded` 에서 해제.
   - 쿨 0 이어도 잠금 중이면 못 쓴다. 해제가 쿨을 다시 초기화하지는 않는다(문서 3-5).
   - 잠금은 이 기믹이 건 것만 푼다 — 사망·메뉴 등 다른 입력 제한은 건드리지 않는다.

## 안 해도 되는 것
- 판정은 보스가 이미 막는다(잠긴 사람의 간파 = 일반 피해). 플레이어 쪽 잠금이 늦게 와도 결과는 안 바뀐다 — 잠금은 **표시·입력 편의**다.
- 일반 전투의 우클릭 쿨 규칙은 그대로(이 기믹 밖으로 확장하지 않음).

## 확인 방법
보스방 HP 20% 아래(레이드 ④ = 간파 릴레이) → MPPM 2인: A 간파 성공 → A 쿨 0 + 잠금 아이콘 → B 성공 → 둘 다 해제.
